# Independently bound reference-number and date metadata

The source rule `header_reference_number_and_date` handles the observed first-page CERC header with a large gap between a reference number and date. Its thresholds, issuer syntax, date forms and exclusions are in `src/local_vector_batch/native_metadata_rows.json`. It does not accept arbitrary columns, later pages, body prose, missing fields, multiple gaps or reporting-format layouts.

The proof splits actual native glyphs only at the existing large-gap threshold, requires exactly two blocks within the configured header area. The reference row must precede body tables; an earlier contact-header grid qualifies only under the explicit prior-contact-header predicate, and partitions every original line glyph exactly once. Each block is read separately through bounded PDFium coordinates. A distinct pypdf layout row must have exactly the same two blocks in the same order, with one unique row match. Non-whitespace codepoints must agree exactly; superscript ordinal layout breaks such as `22\r\nnd` do not replace the literal `22nd`. Different digits, missing characters or ambiguous layout remain held.

The existing `native-table-region-reproof` command consumes the rule automatically. It preserves selected source text/order and all existing font, source identity, independent cell, outside-prose and source-ink gates. The final proof records the rule-file SHA, exact glyph membership/boxes and both independent reading hashes. Reference/date field semantics and legal effect remain unreviewed. Printed dates are not converted into regulatory effect dates.

The v2 contact-header proof retains a preceding one-column source grid only on physical page 1, fully above the reference row, inside the top 18% of the source page, at most 10% of page height and at least 50% of page width. The versioned configuration requires address, six-digit postal code and telephone/fax syntax and excludes operative language. Every original native table cell and grid slot must still match fresh source geometry. All cell hashes, glyph audits and independent reading proofs must pass, and the helper independently rereads every prior-header cell again. Overlap, body tables, missing registry entries, changed cells, unresolved glyphs or absent reader proofs remain held. The complete source grid and raw cell text stay in the region proof.

The literal dual-day header form (for example, `Date: 15th/16th January, 2026`) is retained as two printed days in one header field. This syntax rule chooses no day, creates no normalized deadline and infers no date effect. Tests cover this form as well as boundary, overlap, stale-cell, wrong-page, missing-slot and operative-content rejection. Actual page-quality registration still requires the normal full eight-component source-quality proof and fresh registered decoder.

Outside-table prose retains its ordinary independent-reader comparison first. On failure, `native_prose_reader.map_prose_reader` may reuse the existing source-glyph spacing mapper only when every literal non-whitespace codepoint already agrees and the exact ordered line occurs uniquely in the independent pypdf layout. It disables estimated-cell ownership recovery, preserves raw PDFium text and the complete geometric mapping proof, and retains the region engine's independent ordered-number/operator checks. A source-raised ordinal such as `7\r\nth` may therefore be read as the already-selected `7th`; changed digits, added negations, missing suffixes, alien glyphs or ambiguous layout remain held. This changes reader interpretation only, never original PDF bytes or selected page text.
