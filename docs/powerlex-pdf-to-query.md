# PowerLex PDF extraction and Query data flow

PowerLex keeps the original PDF and the PDF2Data package as the source record. Map/Workbench binds a source and its processed artifacts to the selected document. Query builds a searchable index from that handoff. Desktop and web use the admitted evidence for Ask and use reviewed or explicitly scoped metadata for catalogue views.

| Data type | What PDF2Data captures and retains | What goes to PowerLex Query v2 |
| --- | --- | --- |
| Original and provenance | Exact PDF bytes, SHA-256, source receipt, package identity and artifact hashes. | Source and package identity and source locators. Search evidence resolves to the original and its physical page. The original is retained for PDF viewing and distribution. |
| Page text | Full selected Unicode reading, physical page, page ID, text hash, method and quality. Native and alternate readings remain available in the package. | Admitted selected pages and source anchored text units and chunks. Offsets count Unicode codepoints in that exact reading. Search derives lexical and, where configured, vector entries. |
| Layout and reading order | Available glyphs, lines, bounds, block order, page dimensions and alternate layout evidence. | Used when deriving tables and locating evidence. Raw glyph streams and alternate readings remain in the package or its processed export. |
| Scans, mixed pages and languages | OCR text where applicable, with available word or line bounds, confidence and render details. Script observations and optional region packets record uncertainty and missing coverage. | Admitted text can be searchable. The package retains OCR and region evidence for review. A recognized word or high confidence does not certify layout or values. |
| Tables and cells | Candidate cells and source bounds, row and column positions, merged spans, header associations, blanks, and unresolved slots. Tables may be recorded in physical page fragments. | Query derives table chunks from the saved cells and text spans, carrying labels and joining compatible continuations where supported. Ambiguous geometry and missing cells require source review. |
| Numbers and units | Printed values, signs, percentages, units and dates in page text and cells. Extraction can also emit source anchored fact candidates. | Values can be retrieved in their text, table, clause or authorized profile context. Candidates alone do not prove a number's legal meaning, year, category or unit. |
| Formulas and symbols | Literal text, glyph geometry and configured formula candidates where available. Typography such as subscripts and fractions can depend on glyph position. Image formulas require usable recognition or review. | Query derives formula chunks where it can anchor the expression to saved source spans. Formula tests must check grouping, signs, denominator, subscript attachment, conditions and definitions. |
| Headings, clauses, schedules and appendices | Candidate structure and units with exact quotes, page spans and seams. This can retain physical numbering and heading context. | Searchable units and derived clause chunks where structure and source hints support them. Appendix tables use the table path. Multi-page citations must retain each physical page. |
| Issuer, dates, case, parties and status | Literal headings and candidate metadata from text, geometry and configured fields. A masthead, addressee, party mention, date or procedural phrase is source evidence. | Map/Workbench and authorized profiles can supply source scoped metadata and relationships. Issuer role, issue versus effective date, party role and operative status require evidence checks before catalogue or legal use. |
| Amendments, cited authorities and related proceedings | Literal references, case identifiers and candidate relationships. | Authorized graph projections may carry source scoped nodes and edges. Current legal effect and links across instruments require evidence for the relationship and its dates. |
| Footnotes, provisos and cross-page continuation | Text and layout where captured, plus source anchored units or seams where supported. | Available through page text and anchored units. Association with a table, formula or clause must be checked when it changes the answer. |
| Figures, images, charts, signatures and stamps | The original preserves the visual. The package can hold image region and OCR candidates where configured. | Search can use admitted surrounding text or recognized labels. Figure meaning, signature identity and chart data require a supported extraction and source check. |
| Quality, readiness and repair | Page and package quality, independent reading checks, review flags, provenance and repair receipts. | Admission and evidence handling use the relevant scope and hashes. A ready job or successful index verifies processing state. Content fidelity requires comparison to the original. |

The production handoff carries `pdf2data.processed.v1` artifacts through Map/Workbench. The optional [compact Query data export](query-data-export.md) is a separate adapter with document, page, table and unit records. See [processed export and quality](export-projection.md) and the [local evidence contract](ingestion-contract.md) for the source fields and review rules.

| Change | Work needed |
| --- | --- |
| New PDF or changed original bytes | Process the new source through Index documents, retain its package and original hash, verify the evidence, then build and publish its projection. |
| Saved evidence is missing or wrong | Repair the affected extraction or page representation from the original, retain its provenance, and rebuild the affected projection. |
| Saved evidence is intact, but the index misreads or omits it | Rebuild the affected Query projection from the existing package. For example, merged header spans can repair a flattened table without OCR or PDF extraction. |
| Ranking, query interpretation, answer wording or rendering | Use the existing admitted index when its contract already exposes the evidence. Verify the changed behavior against the original and the evaluation questions. |
| Verified content update | Publish the changed source and projection in a signed library update for web and offline desktop. Track the app release independently. |

Validate in order. Start with the exact originals and pages required by the questions. Compare saved text and layout with the printed evidence, including every requested table cell, formula term and qualifier. Record the page, expected value or relationship, observed value and package hash. Then verify Query can retrieve the complete evidence with valid page links. Finally check the displayed answer on desktop and web. Apply the same checks to representative native, scanned and mixed PDFs before expanding the backlog.
